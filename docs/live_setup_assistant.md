# Live setup assistant

The **Guided Live setup** button opens an optional rules-based conversation for
filling the existing configuration panel. The ordinary Live panel remains the
default. The guided editor occupies the workspace; switching back preserves the
same draft and uploads. It supports only Live beamline setup. It does not add
single-pattern analysis, historical batch analysis, a scan-submission endpoint,
or an independent monitoring service.

## User flow

1. Select a registered Live beamline and enter an IPTS. Discovery reuses the
   existing sample metadata reader. A bounded inspection of the latest eligible
   reduction supplies bank options before chemistry or a library is required.
2. Select samples, banks and the instrument-profile policy. POWGEN can use its
   existing per-run resolver. Reviewed HB-2A configurations use the existing
   facility profile registry, with normalization, collimation and thermometer
   review. NOMAD and SNAP require a supplied profile and an explicit
   physical/profile bank mapping. SNAP also retains product-family and
   reduction-window review. Run-role exclusions and the existing
   initial-monitoring scope remain editable.
3. Select the built-in catalog, build a mini/augmented library from local or
   History CIFs, or choose a portable library archive. Main-phase CIFs have a
   separate control explicitly labeled as a known dominant phase.
4. Confirm sample and environment chemistry, or select a saved configuration.
   A CIF element suggestion is applied only on request. All possible impurity
   elements still need consideration; a closed CIF library limits discovery.
5. Apply an existing Balanced, Rapid or Thorough goal, or keep the current
   settings. Fit limits, exclusions, background, imports and a representative
   curve inspection are available. Advanced controls remain in the Live panel.
6. Review effective values generated by the ordinary configuration converter,
   run the existing read-only experiment preflight, and finish setup. The
   assistant opens the normal Review and start panel. It never clicks or calls
   Start monitoring.

The conversation and manual panel share Live fields. Switching between them
preserves selected uploads and edits. Single-pattern fields are independent.
Each upload surface has a distinct browser identity; controls stay mounted
while navigating questions.

## Text commands and help

All decisions can be made through the GUI. Typed replies use the current
question and existing Live draft. Examples:

```text
POWGEN IPTS-12345
I'm on POWGEN, IPTS 12345
NOMAD IPTS-12345
HB-2A IPTS-12345
SNAP IPTS-12345
12345
the second one
samples A and B, bank 2
elements: Fe, O; can: Al
my sample contains iron and oxygen; the can is aluminium
balanced
please use balanced
rapid
thorough
back
undo
why background
why chemistry
why main
why library
why banks
why profile
why range
why goal
why magnetic
what does background mean?
actually NOMAD
change the samples
```

The bare IPTS number is interpreted only at the experiment question. Numbered
sample replies refer to the first 12 samples explicitly listed in the assistant;
use the sample control for the complete list. Exact IDs take part in
disambiguation: if `2` identifies a sample and a different displayed position,
the assistant asks which identity was intended. `bank 2` always refers to a
physical source bank, and cannot confirm a NOMAD calibration mapping.

[RapidFuzz](https://rapidfuzz.github.io/RapidFuzz/Usage/process.html) compares
misspelled words with a limited vocabulary. It can offer `powegn` -> POWGEN,
`balnaced` -> Balanced, or a nearby sample name. Every fuzzy edit needs a button
selection or a specific pending confirmation; spelling distance is not a
probability. A recognized IPTS stays with a proposed beamline correction, so it
does not need to be re-entered. Unrecognized wording leaves an existing pending
proposal available. Explanations can interrupt a pending decision. `yes` has no
effect without a specific pending choice, and cannot choose among several.

Choices are tied to the draft, question, available identities and displayed
list. Changing them expires the choices. Browser text replies carry the visible
question token, preventing a delayed ordinal from selecting a reordered list.
An invalid part of a grouped sample/bank answer prevents the whole edit; applying
only recognized values requires a separately labeled confirmation.

Chemistry accepts exact symbols and full English element names. Lowercase
symbols can be proposed for confirmation; `CO` and formulas such as `Fe2O3` are
not reinterpreted. IPTS digits, numeric values, sample IDs and bank numbers are
never fuzzily corrected. A beamline-only correction clears the previous IPTS
when changing instruments and asks for the new proposal. Experiment changes
clear assistant undo history, since old sample/profile inputs cannot be restored
without fresh discovery. Other assistant edits can be undone unless the affected
fields have since been edited again.

This is a bounded domain parser, not arbitrary language understanding. Generic
negative/exclusion instructions ask for positive choices; explicit replacements
such as `not rapid, use balanced` are understood. Unknown clauses, conflicting
beamlines and ambiguous `none`/`defaults` replies ask for clarification. More
advanced fit/background settings and file selection continue to use the GUI.
Text is escaped and cannot execute code, resolve arbitrary paths or start jobs.

## Draft and validation behavior

The partial draft remains the existing Live state. `SetupConversation` holds
confirmation signatures, bounded messages and undo metadata rather than a
second scientific configuration. Editing an upstream choice invalidates its
dependent confirmations. A final check is tied to the complete existing
preflight signature, including local input file signatures. Finish setup
rejects a changed configuration. Stale asynchronous discovery and preview
responses cannot confirm newer selections.

A readable folder without an eligible reduction allows configuration to
continue, but cannot produce a successful final experiment check. Unavailable
or inaccessible storage is reported separately. Unsupported profiles,
ambiguous mappings, missing library builds and incomplete chemistry require
correction rather than an invented value.

The normal Analyze configuration is generated by `configuration_from_form`;
the assistant does not introduce another set of preset values. Existing
calibration notices and scientific review requirements remain visible.

## Curve suggestions

The preview uses the registered beamline reader: a bounded stable TOF bank for
POWGEN/NOMAD, the combined CW pattern for HB-2A, or the explicitly selected SNAP
product. It uses native TOF or two-theta limits rather than borrowing POWGEN
units. It retains negative intensities, uncertainties, valid masks
and declared SLOG intensity conventions. The selected fit domain and ignored
regions restrict the private analysis mask. Display arrays are sampled; the
heuristic uses native valid points. Input files are read-only.

The existing measured-pattern envelope estimator provides a background
preview. Low-order Chebyshev descriptions are compared with blocked envelope
errors. A simple model close to the best envelope score can be offered as an
explicitly applied starting value. This is not an independent statistical
validation of the physical background. Broad sample/container scattering,
crowding and other banks can require different treatment. Poor support
withholds a recommendation. Source replacement or changes to selection/fit
regions require a fresh preview before application.

## Validation

```bash
python -m pytest nova/tests/test_live_assistant_language.py nova/tests/test_live_assistant.py nova/tests/test_live_setup.py nova/tests/test_ui_contract.py
```

Tests cover the setup-only boundary, shared Live values, strict chemistry,
dependent invalidation, explicit NOMAD mapping, stale discovery, changed input
files, negative observations, masks, explicit background application, upload
identities and locks while monitoring.
Language tests also exercise phrase equivalents, generated single-character
typos/transpositions, negative instructions, partial answers, duplicate sample
names, ID/ordinal conflicts, stale choices and bounded ambiguity.

A local browser fixture under
`audit/2026-10-29/live-setup-assistant/` exercises synthetic reduced data and
rejects external Galaxy calls. It does not establish deployed NDIP acceptance
or scientific calibration acceptance.
