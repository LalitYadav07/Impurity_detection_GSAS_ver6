# Joint structural search

## Current development status

Model exploration and structural live snapshots use the same prepared nonlinear
service, complete-mode geometry and independent GPX checks. Live snapshots use
the existing acquisition owner and bounded Galaxy transport. Prepared native
starting banks and compatible profile tables can travel with both paths.

The preparation workspace now generates paired examples and trains the
three-channel attention model by default. Clean pairs, noisy feature rows and
independent trajectory holdouts have separate receipts. Trained rankings can
prioritize Model campaign work after isolated native parent/profile admission;
they retain the complete candidate list. An attached model also supplies an
advisory search order for structural live snapshots. The first existing native
point-fit job owns ranking for that acquisition revision, reusing its nuclear
transfer. Ranking uses the current captured counts and masks, the reviewed
producer conversion and the transferred nuclear parent. It recalculates the
parent reference and background on the current grid through the same admission
and inference engine as completed-scan Model campaigns. It cannot reuse a
completed-GPX score for a live revision or filter the reviewed model portfolio.

The live panel shows ranking within the first fit, the leading space-group
families and the resulting pending-model priority. Other allocated point fits
start concurrently. When the first fit returns, its ranking reorders only
models that have not started; active fits keep running. A missing or
incompatible model retains every native candidate in the reviewed order. A
known failed first fit is recorded while the remaining reviewed models are
still attempted. An uncertain dispatch or uncollected result retains its
existing Galaxy handle and requires recovery before admitting more work;
already active fits can finish. Ranking scratch GPXs and measured arrays stay
in the scientific worker; only its bound ranking and transfer receipts are
exported with the fit's checked publications. This default adds no separate
ranking Galaxy job or second nuclear transfer. The standalone native ranking
operation remains an internal diagnostic, not another Live algorithm choice.
Native component timings do not establish fast end-to-end live performance.

Powder sample flag normalization now follows the fields consumed by
GSAS-II's native sample-parameter reader. Numeric pairs such as normal and
anomalous scattering `Contrast` values remain numeric; their zero/one values
cannot become refinement flags. Structural admission compares both contrast
values and accepts their equivalent legacy boolean zero/one encodings without
ignoring a changed physical value. This avoids rejecting a matching prepared
reference merely because a previous transfer encoded numerical zero as false.

The expanded 63-construction cohort has completed all 20,223 native pairs with
no failed constructions. After deduplication, the trajectory-separated split
has 12,538 clean training pairs, 2,875 validation pairs and 2,740 test pairs.
Three simulated observation variants per clean pair expand the training set
to 50,152 examples; they do not count toward the clean-pair requirement. This
is a parent-specific development benchmark, not a collection of independent
experimental measurements. A complete 60-epoch training control has finished,
but its held-out family coverage is insufficient for candidate exclusion.
Architecture and noise-robustness trials continue using validation data; the
rare families and weak examples remain in the cohort. No learned model is
authorized to remove candidates. Broader parent-reference sampling, portable
optimizer recovery, aligned NDIP images and complete real-experiment/UI
acceptance remain open work. These
changes have not yet been deployed as an accepted preparation release.
Component measurements below retain their original scope; they do not prove
complete-workflow speed, structural recovery or NDIP latency.

Paired example generation draws shared parent cells before testing individual
children. Child trajectories are now admitted at those fixed parent contexts,
using the same metric transformation as the final native examples. A rejected
combination redraws the whole child ray inside the original bounds, retaining
all coordinates, amplitude steps and trajectory identities. It cannot replace
a parent cell for one candidate, clip a point or omit an inconvenient family.
An infeasible parent-only control or an exhausted trajectory scope still fails
the block. This sampling change does not widen an existing model's verified
parent-reference envelope; that requires new native curves and held-out tests.

Parent-reference sampling also does not enlarge the child's reviewed cell
domain. An incompatible parent-only control retains the declared cells and
bounds and fails with a specific scope-conflict message. Bounded, request-bound
diagnostic receipts carry that reason through native batches and single Galaxy
jobs. Failed members remain failed while successful siblings can be published;
the diagnostics cannot create a scientific result or a preparation certificate.

New paired-example libraries automatically divide each complete trajectory
portfolio into smaller scheduling units for children with many declared modes
or a dense calculation grid. This changes job granularity only: every original
trajectory, amplitude step, seed, physical coordinate and bound remains in the
plan. Existing saved plans keep their captured slices. Actual native dimensions,
granted CPUs, memory and output-size checks still control worker admission;
declared mode counts are only a conservative estimate of computation cost.

A native unit started late in a batch receives only the remaining batch time.
If that shortened budget expires, its verified interruption remains pending
and the queue starts it alone with one fresh full budget, preserving its logical
attempt. Partial scientific outputs are not published. A unit that exhausts
that fresh budget becomes a visible failure requiring review; technical
failures and cancellations do not enter automatic deadline recovery. The queue
retains the acknowledged Galaxy job and result identity across recovery.

CPU attention training now saves owned, atomic numerical checkpoints during
warmup and after complete epochs. Repeating the identical training request in
the same surviving worker directory verifies the feature cache and restores
the parameters, AdamW moments, learning-rate schedule, random streams, visited
rows and validation-selected incumbent. Changes to data, partitions, numerical
allocation or implementation require a new run. Completed published outputs
are verified and returned unchanged; damaged published files are not silently
replaced. Feature caches stay in worker scratch. For a long three-curve training
run, a worker yields at a complete warmup or epoch checkpoint before its native
deadline. Only two bounded data files containing numeric optimizer state and
its typed receipt enter the acknowledged job output. The queue verifies the
creating job and captured input hashes, then starts a fresh worker with the
same logical attempt and full epoch target. Every continuation must advance
the checkpoint counter; damaged, changed or nonadvancing states remain visible
failures. Partial work is not a trained model or scientific qualification.
These optimizer files do not enter downloadable model libraries. This recovery
does not apply to the separate structural fit optimizer.

Structural Model and Live acquisition receipts separate the current worker's
preparation from fitting and independent GPX checks. The displayed combined
service time is a subtotal of native worker time; other worker tasks, Galaxy
queueing, startup and transfer are additional. Loading a previously prepared
library does not count its historical build time as current computation.

Portable raw TOF peak chunks group the bytes of their original float32 values
before lossless compression. Decoding restores every bit before the existing
array hashes and native checks run. Large chunks retain the legacy encoding
when byte grouping would exceed the existing transport element limit. Legacy
archives remain readable, and resuming or repairing an existing store preserves
its sealed file hashes. Smaller archives do not establish current-context
compatibility, native provenance, convergence or a complete-search speedup.

Current-context starting curves have two explicit roles. Portable native banks
retain their creating-job admission and exact-context reuse. Large reviewed
TOF profiles can instead compile continuous starting proposals automatically
when those native banks do not match the actual context. The proposal path
retains exact fixed-cell response reuse, native geometry and structure factors,
the complete joint starting portfolio (185 points when displacement modes are
present), and the original proposal-step selection. It
uses native peak cores and supported interpolated tails. Tabulated profiles,
unsupported corrections and small workloads keep the original native path.
The one-million-reference-bin scheduling threshold avoids compiling a large
table for small work; it is a performance policy, not a scientific exclusion.

These proposal banks are labelled `starting_proposals`, with zero
`native_curves`. They cannot receive a native-production certificate or enter
the native-bank registry. Only their creating process owns reuse; fresh workers
regenerate into their new output directory without modifying the saved bank.
Imported tables need their creating-job admission and current-context checks;
an uploaded qualification flag cannot grant authority. Scale/background profiling,
accepted optimization steps and independent GPX checks remain native. Gaussian
conditional nuisance fitting solves its bounded least-squares problem from
the actual native design, so screening-coefficient roundoff is not carried into
the native optimization trajectory. Receipts distinguish this execution from
portable native-library reuse. Component and matched-work controls do not
establish optimization convergence, complete-catalog recovery or NDIP latency.

The structural workflow adds a nonlinear backend to **Refinement → Model
exploration → Structural displacement modes**. It uses GSAS-II for diffraction
and instrumental profiles, and shares the existing campaign ledger, Galaxy
admission policy, process cancellation, independent audits and result viewer.
It does not replace RADAR phase discovery, custom nuclear recipes, magnetic
Hessian/grouped optimization or live magnetic posterior analysis.

## User workflow

1. Select the target RADAR or recipe GPX and inspect its parent.
2. Choose **Structural displacement modes**. The application uses one complete
   coordinate workflow; an optimizer choice is not required.
3. Optionally select a well-refined **Parent reference GPX**. Its named parent,
   exact setting, site labels, species, occupancies and isotope selection must
   agree with the target. The reference supplies fractional coordinates and
   ADPs; the target supplies observations, instrument, parent cell, background,
   sample terms and retained secondary phases.
4. Declare a rational k, discover a bounded catalog with ISODISTORT and review
   the selected children. Discovery still uses the existing Method-2 scope;
   it is not an exhaustive enumeration of every supercell or mixed-irrep group.
5. Review displacement/cell bounds, starts, numerical allocations, contact
   assumptions, exact scans and whether to follow newly published matching
   GPXs. Approve the finite plan, then start it.
6. Inspect each fitted curve, residual, reflection ticks, mode amplitudes and
   disposition. Download or open the exact independently audited GPX in hosted
   GSAS-II. These point estimates remain **optimization unresolved** rather than
   being promoted to unique structures or native convergence certificates.

New UI plans retain every independent physical mode in each included child.
The older selected-mode executor is retained internally to read and recover
sealed historical plans; it is not an alternative new-setup option.
Only demonstrated uniform-origin gauges are
removed. Gauge reference holds in exported GPXs preserve that physical space.
One campaign work unit owns a complete child and its internal starting portfolio;
there is no exponential expansion of sign combinations into separate Galaxy
jobs. Independent children and scans use the existing bounded worker pool.

## Scientific scope and safeguards

- One transforming, commensurate, nonmodulated nuclear phase per selected
  histogram. Fixed secondary nuclear phases are retained through calculation
  and export. Each bank is analyzed independently.
- All included independent displacement and symmetry-allowed lattice
  coordinates can vary together. No mode is discarded because it scatters
  weakly. Numerical failure is not subgroup exclusion.
- Exact parent anchoring intersects the atom-site and displacement-formula
  printed-precision intervals. ISODISTORT can round a halfway value in opposite
  directions in those two tables. A unique unchanged parent orbit must lie in
  both intervals; disjoint intervals, incomplete site arrays and unresolved
  mode origins require review. The existing precision caps, multiplicity
  checks and complete zero-distortion native-profile comparison remain active.
- Occupancy, ADPs and instrument parameters stay fixed. The common histogram
  scale is bounded to exp(±0.3); a bounded additive correction to Back;0 varies.
  Higher background coefficients and additional background terms are retained.
  The actual nuisance bounds are recorded in each fit receipt.
- The contact screen uses versioned, checksum-bound MP/COD aggregate minima
  as explicit assumptions. These are not universal physical laws or model
  probabilities. Unqualified partial-occupancy contacts fail for review.
- Source phase/HAP constraints, parent restraints, nonzero parent HStrain,
  anisotropic sample broadening and nontrivial texture require additional
  transfer implementations. They are refused rather than silently stripped.
- Exact-cell native response reuse is independently checked. Exclusions,
  masked grids, retained secondary phases and nonlinear extinction use a full
  native fallback instead of relaxing the reconstruction tolerance. Models
  above the 256-coordinate response-cache limit also use the complete native
  calculation; their coordinates are not truncated or rejected by that cache.
- For the reviewed single-phase, unmasked PNC/PNT native driver, the service
  records reflection responses during an already-required Rietveld evaluation.
  Original native peak functions, structure factors and constrained mode
  derivatives supply the calculations. No division by parent F² is used, so
  a zero-intensity reflection can acquire intensity under distortion. Responses
  belong to an exact cell and fixed profile context; the owned numeric cache
  has a 64 MiB limit. Unknown native drivers and unsupported contexts retain
  full native evaluation, with a recorded fallback reason. Temporary lattice
  finite-difference probes do not construct unused response matrices. Every
  accepted displacement proposal and independently reopened GPX still receives
  the existing native comparison. This reduces duplicate calculation but does
  not precompute general nonlinear cell/profile changes or certify a global
  minimum. Native context ownership requires separate processes for parallel
  candidates, never concurrent GSAS-II adapters in one process.
- The reviewed TOF capture can store the original float32 peak windows with
  their double-precision correction factors, rather than a second weighted
  sparse matrix and repeated row indices. An installed, checksum-matched
  helper applies those columns in the original reflection order. The native
  driver still calculates the entire accepted curve and supplies every raw
  peak; this representation introduces no new peak calculation or interpolation.
  Dormant zero-F² reflections and empty columns remain present. Capture,
  reconstruction, mode derivatives and final GPX audits retain their existing
  checks. Captured arrays are immutable and owned by the scientific process;
  this matrix type is not imported from portable libraries. Unsupported
  arithmetic controls or a missing helper retain the existing CSC capture.
  Numeric cache accounting includes the compact arrays and retained kernels;
  the 64 MiB resident limit and complete physical parameter set are unchanged.
- Starting-curve construction reuses the exact fixed-cell native profile for
  displacement-only proposals. It uses the same required-pass capture engine
  as the shared fit service; it does not construct a separate Pawley response.
  Cell changes still use complete native calculations. All starting points,
  contact checks and secant-step choices remain unchanged. The earlier native
  reuse schedule measured 52.45 → 33.38 s preparation in one Linux/amd64 TOF
  control, with all 69 curves agreeing to 1.8e-15 relative error. That historical
  measurement does not measure this newer schedule or complete workflow latency.
- An independent saved-GPX calculation must agree within 1e-8 relative error
  and 0.01 supplied standard deviations. Export verifies active mode variables,
  origin holds, cell freedom and fixed instrumental values, with no stale
  covariance. Ordinary GUI continuation does not enforce the contact screen or
  the original search box; this limitation is recorded in its contract.
- Both saved GPXs are reopened independently to verify measured intensities,
  supplied variances, likelihood bins, Rwp normalization and weighted cost.
  Extra likelihood omissions become exact-bin native exclusions. Valid
  measured weights outside the current fit interval are retained for later
  changes of limits. A different normalization convention is refused.
- Cell-expansion admission runs before either structural executor begins
  native work. The worker audit reconstructs the physical displacement/cell
  bounds and complete active set from the sealed parent and child CIF; it
  independently checks positive bounded scale and constant background.
- Native GSAS-II Rwp and the fitted-bins-only diagnostic are separately named.
  Excluded strong peaks remain in native Rwp normalization. Neither value is a
  transition probability, model posterior or automatic counting-stop rule.

## Shared completed/live API

`gpx_recipe.structural_live.service.prepare_model` prepares geometry and native
starting curves once. `fit_snapshot` fits one complete reduced observation.
`StructuralSession.update` replaces observations and carries only starting
parameters forward, never a previous cumulative likelihood. It rejects stale
or changed same-revision observations, grid/protocol changes and exposure
resets. A failed update leaves the previous publication intact; duplicate
updates do not run another fit.

Restoration, duplicate returns and warm starts verify the sealed receipt and
both GPX digests. Artifact manifests use confined relative paths so a session
can be relocated without rewriting its sealed scientific receipt. A missing
or changed artifact requires repair/re-export; it is not silently refitted or
treated as a reusable publication. This session serializes updates within one
owner instance, not across independent processes.

Optional recovery deadlines retain the independently evaluated incumbent.
The receipt names budget-expired stages. Native identity, objective and physics
errors still propagate and prevent publication; recovery is not a general
exception suppression mechanism.
Recovery uses the same owned response evaluator for displacement derivatives,
anchored by a complete native curve at every derivative request. Its scores,
cell secants and acceptance checks remain original native calculations.
Unsupported contexts retain the full native derivative path. A recovery receipt
records the evaluator counters at admission and afterward, since its response
cache can have been populated by the main fit. The final reported objective and
Rwp follow the retained recovery result, rather than the earlier main fit.

The reduced-profile adapter selects one bounded, process-local peak store for
fixed-cell, fixed-profile workloads; the Model magnetic residual adapter shares
that store across fresh native contexts in the same process. Each context has
its own accounting and independent native constraint ownership. Changing counts,
weights, moments or nuisance coefficients does not copy an earlier likelihood;
only identical peak-function arguments and grid windows can reuse numeric shapes.
The aggregate shared store has one 64 MiB allocation and one entry ceiling.
Native implementation changes clear its qualification and contents. Arithmetic
control changes also clear numeric shapes, including between two driver calls
inside the same owned scope. The read-only control check currently supports
Linux/glibc x86-64; unavailable evidence uses the original native calculation.
Sticky exception-status flags are excluded from this identity. Inherited
adapters detach from a parent process's store before reuse; this does not make
forked GSAS-II state a supported concurrent execution mode. Spawned workers own
independent stores. No file transport or cross-worker cache is introduced.
Ordinary variable-cell/profile workloads keep original native rendering: a
complete 185-start control exposed a regression hidden by a shorter rendering
test. Dense TOF workloads use a private bounded memo when one actual native
powder histogram has at least 16,384 reflections and all powder histograms use
PNT profiles. The selection inspects complete native reflection lists, not
the compound, mode count, requested workers or an uploaded permission flag.
Mixed and unsupported profiles keep the original changing-geometry policy;
the existing per-driver cost probe can still bypass unprofitable memo work.
Cell and profile parameters remain free, and every reused shape must retain
the same exact native arguments and arithmetic controls. Explicit zero-byte
reference controls still use the untouched native calculation.

A complete matched 41-pattern dense TOF control retained all 17 independent
native checks per variant. Every curve, label, axis and background was
bit-identical; measured time decreased from 976.7 to 800.4 seconds. This is a
child-rendering measurement including cold context construction, not a full
preparation or NDIP latency claim. The private dense-workload memo and shared
fixed-geometry memo each retain the original 64 MiB/16,384-entry bound. This
selection does not alter the scientific parameter set or authorize screening.
The exact structural forward renderer also uses the complete compact native
record arrays already used by proposal rendering. Legacy dictionary readers,
original per-peak rendering and native-anchor fallback remain available. The
same full 41-pattern control then took 740.0 seconds with all four output
arrays identical to its matched original control and all 17 independent
checks retained. The current complete native acceptance suite passed 316
tests; this does not establish whole-preparation or deployment latency.
The memo supports the reviewed native PNC/PNT peak routines.
For the reviewed unmasked, single-phase TOF starting-curve path, an installed
worker helper can batch calls to the original Fortran peak routine. The helper
retains the native float32 arguments and outputs and the original double
reflection summation order. It removes repeated Python calls and an unused
quadrature calculation; it introduces no peak formula or interpolation. All
current atomic scattering, cell-dependent peak arguments and profile edits are
still computed by the native scalar functions. The renderer retains its
independent, array-identical whole-native anchor check.

The helper is compiled once while building the Model worker image, with fused
multiply/add and fast-math disabled. Its reviewed C source participates in the
scientific package identity. Frozen worker bundles contain that source as data
and resolve only the matching helper installed in the image; they never load
an executable from an imported preparation library or job folder. Unsupported
ABIs, arithmetic controls, ownership changes or insufficient scratch space use
the original calculation. The existing 64 MiB forward-workspace bound includes
the extra native buffers; no reflection is removed to meet it. Batch counters
report actual work separately from portable-kernel hits.

The exact-input memo reuses only exact scalar arguments and exact grid windows; grid contents
are hashed on every native driver call. Reflections, intensity corrections and
native summation order remain unchanged. No interpolation or uploaded numeric
predictions enter this cache. Exclusions, secondary phases and extinction still
use their full native equations. Unknown drivers, native multiprocessing and
active response-capture hooks bypass the memo, and temporary functions are
restored on exceptions. Each adapter reports its own reuse and bypass counters,
separately from process-store occupancy. The 64 MiB accounted-cache ceiling and
entry bound do not describe total native process memory. Periodic bounded probes compare estimated native work saved
with measured bookkeeping cost. An unprofitable driver call immediately
returns to the original peak functions; later driver calls can probe again.
The bypassed native tail is not included in the observed peak-call counter.
This can reduce repeated rendering, but does not itself solve
portable preparation or nonlinear cell/profile adaptation.

Variable-cell/profile calls can independently avoid masked-array temporary
objects when the reviewed native driver receives an entirely unmasked,
contiguous float64 axis. `NativeUnmaskedAxisView` passes a zero-copy plain
array view to that original driver; it preserves the reflection loop, native
kernel calls, summation order and owned histogram arrays. Real masks,
unusual storage, native multiprocessing and active response-capture hooks
keep their original arguments. Temporary driver wrapping is restored on
exceptions. Explicit zero-byte native reference controls do not enable this
optimization. Receipts report its selection and conversion/bypass counters
separately from peak-cache accounting. This does not make a prepared bank
compatible with a changed cell or profile.

For reviewed single-phase PNC/PNT structural contexts, lattice proposals can
stream the original native peak derivatives together with native reflection
geometry and intensity probes. One complete native anchor restores the
scientific state. The probes' unrendered arrays never enter an objective,
screening score, observation, exported GPX or uncertainty calculation.
Derivative arrays are accumulated immediately under a bounded workspace;
they are not retained for every reflection. A reflection entering or leaving
the native inventory makes that entire lattice direction use original native
differences. Unknown native code, extracted intensities, secondary phases,
masked contexts, nonlinear extinction and unsupported peak conventions also
retain original differences.

These directions are optimization proposals, not qualified exact Jacobians.
Every accepted step uses the complete native objective with freshly profiled
scale/background coefficients. Stalled or apparently stationary proposals,
including the outer small-progress stopping rule, require a fresh native
cell-direction retry. Deadlines between probes restore the genuine native
state before returning. Receipts distinguish scalar probes, full native
anchors, membership fallbacks and reused directions. This is one automatic
execution policy; the force-native argument is an internal regression oracle,
not a user accuracy/speed choice. It does not establish portable structural
acceleration, global optimization, covariance validity or faster whole-catalog
execution by itself.

`ReducedObservation` accepts unknown exposure. Its `mask=True` means usable;
the snapshot adapter explicitly accepts `invalid_mask=True`. Reduced intensity
and supplied variance are never converted into invented counts. Verified raw
counts retain a separate count/exposure contract.

The shared acquisition adapter is
`gpx_recipe.structural_live.acquisition.prepare_acquisition` followed by
`StructuralAcquisition.update`. It runs in an owned scientific process under
the existing WebMON acquisition owner; it has no source polling loop.
Magnetic preparation and structural acquisition share
`gpx_recipe.live.nuclear_transfer.prepare_nuclear_snapshot` for transferring
the reviewed nuclear reference onto the producer's uniform TOF grid. The
original nuclear GPX and instrument remain immutable. Model-specific magnetic
site/catalog review stays separate from structural displacement construction.
Released instrument refinement flags in a recipe output are deliberately held
for transfer; both initial and current numerical X/Y/Z values are preserved.
The final source check uses the originally requested GPX checksum, so an edit
after native loading cannot acquire a new reference identity unnoticed.

The acquisition contract binds the prepared model, native grid/fit exclusions,
reviewed exporter geometry and normalization, physical bank, producer identity,
run/sample scope and spectrum marker. The owner supplies an archived snapshot
receipt and an explicit monotonic revision. Signed reduced values and supplied
uncertainties are preserved; exposure may remain unknown. Newly measured bins
can replace zero-weight placeholders without rebuilding physical preparation.
Every snapshot supplies its own likelihood and native normalization masks.
Changed grids, spectrum markers, banks or producer/sample declarations require
review. A declared mapping is not independent evidence that a live producer
actually retains that configuration.

Snapshot input lineage is sealed before fitting. POSIX writer ownership and a
fresh durable-ledger read prevent recovered owner instances from overlapping
or replacing newer publications with stale updates. Duplicate delivery verifies
the existing receipt and both GPXs, without another nonlinear fit. Restoration
also recomputes the observation identity from its archived raw snapshot. A
failed new fit leaves the previous publication intact. Only previous parameter
guesses carry forward, together with the existing complete starting policy.
Point-fit results carry no structural posterior, model probability, exclusion
permission or counting-stop recommendation.

Acquisition contexts contain measured experiment data. They belong to private
scientific job/History artifacts, not portable theory-only preparation libraries.
The closed `structural-snapshot` native operation now carries a self-contained
or shared-input reviewed Model job, its optional parent-reference GPX, reviewed anchor snapshot,

Optional preparation metadata is captured alongside the model inputs. Original

Galaxy-template metadata as Model exploration. A copied manifest does not
attest its own curves. Missing authority or incompatible physical context keeps
the existing native requalification/rebuild policy.

Each operation currently reconstructs an owned structural acquisition context;

Original prepared banks may help only where their actual-context compatibility

The future Galaxy template publishes independently checked point-fit GPXs in

## Packaging and qualification

### Cold prepared-bank provenance

The preparation worker can publish a compact, data-only native-origin receipt
alongside its ordinary result ZIP. The fixed Galaxy command announces that
receipt's checksum in job stdout; scientific subprocess output remains in the
console dataset. A later tool invocation obtains creating-job metadata through
the Galaxy template, separately from its uploaded scientific request. A JSON
field claiming native verification cannot establish this provenance.

For a compatible current structural context, an original receipt from the reviewed
Model Campaign wrapper permits reuse of the complete prepared bank after three
fresh native profile probes. The reader still checks every declared start,
chemical feasibility, array shape, grid, checksum and physical context. Every
subsequent fit and exported GPX retains its independent native acceptance
checks. The probes check the current reader/context; the producer evidence
binds the complete bank, including the curves not selected as probes.

For a single nuclear phase with zero extinction and an unmasked PNC/PNT grid,
the bank also retains its native reference background and an identity with
only intensity normalization and existing polynomial background coefficients
removed. A later nuclear fit can change histogram scale, the single-phase HAP
scale or those background values. The reader then uses the exact affine
relation `(prepared_curve - reference_background) * scale_ratio + current_background`.
The scale ratio includes both native intensity-scale factors. The current
background is evaluated by GSAS-II; it is not fitted to the prepared curves.
Native scale floors, a conservative foreground roundoff bound and the complete
remaining dependency identity guard this operation. This does not change any
fit freedom or copy experimental observations into preparation. Recorded
proposal steps remain heuristics from the preparation reference.

The background definition/order, cell, displacement basis, occupancies, ADPs,
instrument/profile values, grid, masks and chemistry remain dependencies.
Secondary phases, nonlinear extinction, exclusions and unsupported background
terms retain complete native reconstruction. This is one automatic policy,
not a user-selectable approximate solver. The qualification receipt records
any affine nuisance binding and its numerical error bound. Origin checks and
fresh native probes apply after rebinding too.

If the receipt is absent, changed, inaccessible, produced by an unreviewed tool,
or incompatible with the current scientific implementation, the normal native
reconstruction remains in force. A changed physical context also rebuilds.
Receipts do not make another cell, profile, grid or unsupported baseline compatible.
Reuse/reconstruction state and native-probe errors are recorded in
`starting-curve-contract.json` and the resulting structural service receipt.

Portable libraries retain only bounded receipt lookup references. NOVA uses
the current user's authorized access to the same Galaxy site to select the
original small dataset; it never follows a site URL supplied by a bundle.
Origin lookup failure does not invalidate checked preparation arrays. Reuse
across accounts, unavailable original Histories, sites and compatible software
upgrades still requires additional qualification; downloadable files alone do
not establish standalone trusted reuse. No API key or signing secret is stored
in a library, receipt, numerical request or child-process environment.

The future Galaxy template introduces these inputs/outputs at Model Campaign
0.2.17. Updating that template does not activate an image or alter the deployed
tool XML. A coordinated immutable release and actual Galaxy acceptance remain
required.

Runtime code never imports benchmark runners or laptop paths. Superseded
interpolation engines and independent prototype schedulers were not installed.
The packaged contact files, policy and source code are bound by the scientific

## Bounded native kernel chunks

The shared TOF renderer accepts a natively qualified primitive kernel chunk.
It recomputes the current structure factors, reflection membership, intensity
corrections and background. A stored peak is used only when the original
compiled float32 shape and translated-axis inputs are identical. Other peaks
use the original native function. Actual coordinates and measured arrays are
retained; no grid resampling, interpolation or old intensity is introduced.

Chunk arrays are immutable and data only, bounded at 64 MiB after expansion.
Metadata and array headers are checked before loading. Imported bytes carry no
native qualification: every stored peak is recalculated and compared bitwise
before this process can use it. A bounded process-local qualification index
recognizes reloaded identical content, but it is neither exported nor inherited
across a fork. Changed native functions or runtime identity require the native
path. This check is an explicit first-use cost; it must be included in future
worker-lifecycle benchmarks.

arrivals and exact-byte repair, and retains a declared missing-chunk count.
It streams deterministic parts of at most 128 MiB, below the native transport
limit, while retaining the 2 GiB store bound. Parts can be imported out of order
and resumed after cancellation. Stored/imported coverage describes file
integrity, never fitted results or scientific qualification.

The complete public C2/m prototype retained array-identical curves for 740

initial curves plus loading and three native checks, not proposal-step
calibration or nonlinear refinement. The new bounded format still requires

instead of polling a trainer indefinitely. Explicit retry retains completed
blocks and the original denominator.

Completed rankers can now travel in the same immutable structural input
snapshot as native starting banks and shared profile tables. The capture binds
parent CIF, instrument file, bank grid, model metadata and numeric weights.
Exact candidate definitions determine routes; a protocol selecting fewer k
families never acquires other candidates from a broader trained library.
The shared worker-side advisory reader retains every protocol candidate and
falls back to the complete native order on corrupt assets, missing ranges or
unsupported patterns. Its caller must select the exact checked entry: a
multi-bank instrument file's checksum alone cannot identify the right bank.
Model campaigns now run isolated native source/profile admission in their
first scientific chunk and save the source-bound advisory order for later
dispatch. Structural Live/Webmon snapshots use this same admission/inference
engine inside the first point fit, bound to the actual captured counts and
revision. Both paths retain all candidates. Scientific qualification of
candidate filtering and complete real-NDIP handoff acceptance remain open.

Library manifests use compact JSON and check the same encoded byte count that
the reader accepts. This avoids admitting a multi-bank plan whose pretty
printed file is too large to reopen. The metadata and file-count limits remain
in force; larger scopes must be rejected before calculation rather than
silently omitting candidates or trajectories.

Entry admission and native dispatch intents use the same process-local plus
file-lock helper. Separate objects in one worker remain serialized when a
container-shared filesystem provides process-scoped file-lock semantics. A
new viewer still recovers the original dispatch rather than posting a second
job. The cross-process file lock remains in place.

These application dependencies do not grant permission to prune candidates.
Complete real-NDIP Live/Webmon acceptance, portable recovery after worker loss,
broader sampling and scientific qualification remain required. Identical
training requests recover worker-local atomic optimizer checkpoints; verified
complete segments also continue through fresh workers. Interrupted jobs and
partial segments do not publish successful training receipts.

## Three-curve attention development

The replacement representation under development has exactly three learned
channels: reference intensity, current intensity and current minus reference.
Both patterns use one physical Q grid, one shared intensity scale and the same
asinh contrast. The signed difference is calculated from background-subtracted
native intensities before compression. Independently normalizing the two
patterns would erase real intensity changes; normalizing the residual by its
own maximum would inflate arbitrarily weak changes. Coverage masks and Q edges
remain preprocessing metadata, rather than fourth or fifth learned channels.
Existing eight-channel portable libraries remain unchanged and readable. New
workspace preparations use three channels; old weights cannot be loaded into
the three-channel architecture. Neither format currently permits pruning.

`preparation.structural_attention.network` combines local convolutions with
a four-head attention layer over ordered Q-region tokens. Convolutions extract
peak detail before token pooling. Position encoding retains the ordered grid,
and coverage metadata masks missing regions. An otherwise matched encoder
without attention is an experimental control, not another user-facing mode.
Attention is a hypothesis about useful cross-pattern context, not evidence
that top-five accuracy has improved. Overall, per-family and weakest-family
recall must be compared with a frequency-only baseline on identical splits.

`preparation.structural_pairs.generate` builds a separate, versioned native
paired-pattern pilot. Each physical trajectory has a common parent-compatible
cell context and a parent-only control. Parent metric variation is sampled
independently of the child family. Only the parent-invariant part of the
child's metric is replaced; every atomic mode and symmetry-breaking strain
coordinate is retained. Final points must pass the original physical bounds
and chemistry checks. Invalid blocks fail rather than clipping a distortion
or discarding a weak-scattering family.

Native child patterns are rendered first. Native calculated parent references
are rendered in a separate owned pass, since GSAS-II global constraint maps
cannot be interleaved safely. Parent-only controls record their shape agreement
and intensity-scale ratio against that independent reference. These controls
do not establish equivalence of every anisotropic ADP transfer or qualify a
classifier. All steps, null controls, aliases and noise siblings of the same
physical trajectory remain in one partition. Sharding preserves that identity.

The prepared reference is a calculated undistorted parent at a declared cell.
A measured pre-transition reference introduces its own noise, background and
possible hidden distortions. Training with calculated references does not
validate substitution of measured references. Both cases need separate
acceptance, including anisotropic thermal cell changes and weak signals that
finite-resolution powder data cannot distinguish. No three-curve pilot score
currently authorizes candidate pruning. Compatible trained models can
prioritize pending native work in Model/Live execution.

`structural_paired_blocks.read` validates the separate three-curve source
format before allocating its bounded arrays. Parent-only controls must retain
both native shape and the same intensity units: an arbitrary scale fit is not
enough for a shared-scale difference channel. Child identity, complete
trajectory slices, parent-cell positivity and a constant reference within
each trajectory are checked. Source hashes establish identity rather than
native provenance. Imported flags cannot authorize scientific screening.

The shared cohort assembler now supports these checked pairs through
`assemble_pairs`. Alias closure, noise generation, set-valued targets and
candidate routes use the existing implementation. New paired cohorts require
every class in independent training, validation and test trajectories. Noise
variants cannot manufacture independent class support. An infeasible split
requests more sampling rather than silently leaving a family out of validation.
Historical eight-channel cohorts retain their original assignment policy.

`structural_paired_store` writes bounded three-channel working files using the
shared batch reader. Large training sets do not require materializing all
features in RAM. Completed caches bind their numerical bytes and retain all
source references and augmentation provenance. The three-channel signed
residual is normalized as an intensity feature, never as the legacy coverage
channel occupying the same numerical index. These working caches are not
portable weights; the trainer below produces the separate inference artifact.

## Three-curve attention weights and native inference

The shared trainer now accepts validated three-curve cohorts and trains the
fixed convolution/attention architecture with 128 Q-region tokens and four
attention heads. Its version-two readout normalizes the 64 hidden features
before GELU. A many-family development run exposed the original readout
saturating entirely to zero despite input-dependent convolution/attention
features, leaving only class biases. The normalization changes neither the
three physical channels nor the candidate definitions, physical bounds,
generated examples, labels or independent holdouts.

Training-only channel scales preserve the signed difference.
Strong clean training prototypes precede a clean-to-noisy curriculum and are
replayed alongside subsequent data batches. Each update adds at most sixteen
training-only representatives to at most sixty-four data rows; larger family
catalogs rotate through all representatives. The balanced pass and its
complete-pool coverage pass both retain clean replay. Repeated representatives
do not increase the unique training-pair count, and no validation/test curve
enters replay. One complete-pool training-only comparison retained all sixteen
strong representatives with replay; the matched normalized model without
replay retained only six in its top five. That result establishes retention
on those training examples, not held-out accuracy. Epoch receipts therefore
separate strong training recall from independent validation scores. A
published checkpoint must still have seen every declared training row. Validation
selects among eligible checkpoints using macro family top-five recall, overall
top-five recall and loss; the test fold is scored afterward. Per-family and
worst-family recall accompany overall recall and a training-prior baseline.

Training checks the actual hidden readout on strong training-only
representatives after warmup, after each epoch and after restoring the
validation-selected checkpoint. A completely inactive readout fails before
test scoring or model publication. The check preserves dropout/random state
and reads bounded batches. Readout activity alone does not establish
discrimination, accuracy, calibration or scientific adequacy; those require
the independent scores and real-data acceptance described above.

Portable attention parameters occupy one typed numerical plane. Tensor names
and dimensions come from installed code, never an uploaded layout or program.
The six-array file retains the existing sixteen-array and 32 MiB transport
limits. The shared ranker reader dispatches by the versioned data schema;
existing eight-channel files remain readable without a user-facing method
switch. The original version-one three-channel architecture also remains
readable through its fixed installed tensor layout. A metadata label cannot
reinterpret weights from a different architecture. An inactive readout yields
no ranking scores and retains every native candidate, including when reading
an older library. Native preparation snapshots retain the same parent, bank and exact
candidate-route integrity checks for both formats.

Three-curve inference requires a freshly calculated parent on the actual
acquisition's Q grid. Native admission can calculate it from the checked GPX
at its current parent cell and fixed physical parameters, without a refinement
or a GPX write. Saved calculated arrays and interpolated old preparation
curves are not substituted. Unsupported masks, contexts and empirical
out-of-support patterns retain the complete native search. A saved screening
flag never authorizes pruning. Measured pre-transition references remain a
separate scientific qualification requirement.

The default preparation workspace now creates paired example blocks and a
three-curve training dependency. Every bank shares its declared parent seed,
metric interval and trajectory identities across all children. Old saved
settings and entry identities are preserved. Mixed representations or changed
parent sampling cannot form a training plan. The default parent reciprocal-
metric interval for newly declared libraries is 0.0001–0.005 in the native
parent metric norm. Saved intervals retain their exact values. This expands
the simulated nuisance domain; it does not enlarge an existing model's
admission bound or establish broad thermal-cell coverage.

Generation exports the same `examples.json` and `examples.npz` artifact names,
using versioned paired content and lossless storage. Native construction GPXs
stay in worker scratch. The typed training plan binds that representation and
every block's hashes. NOVA checks the metadata and hashes without loading raw
curves; the worker repeats the physical controls before building the three-
channel feature cache. Export, restore and later model-packet handoff retain
the exact native candidate routes and require a freshly calculated reference.

Offline structural training has a separate 7,200-second native deadline,
checked by the same installed contract in NOVA and the Galaxy entry point.
The queue uses that deadline for each allocated training segment. Three-curve
training cooperatively saves a complete checkpoint at an internal 5,400-second
budget, allowing time for input checks, collection and cleanup. The budget
does not reduce the declared training work or trigger test-holdout scoring.
Other
native operations retain their 600-second limit, and native generation batches
retain their existing scheduling and cleanup limits. The longer ceiling is
not a wall-time guarantee. Real NDIP queue,
allocation, full-data training and experimental acceptance remain to be tested.

Local, unsegmented preparation on an MPS-capable Mac now uses the same trainer
on that device automatically. The three physical channels, architecture,
loss, sampling, candidate labels and holdouts are unchanged. CPU execution
and the CPU worker-continuation format remain the path for Linux/NDIP jobs,
segmented workers and imported optimizer continuations. An existing CPU
checkpoint stays CPU-owned; an existing MPS checkpoint requires its exact
device/runtime and cannot silently restart with a different optimizer.

MPS working checkpoints commit device random state and the ordinary audited
CPU optimizer representation together in one bounded atomic numerical file.
They are not portable library assets. Interruption preserves the previous
complete checkpoint. Adaptive pooling uses the same native floor/ceiling
windows when MPS does not support a particular length; maximum-pool ties retain
the native first-maximum derivative. CPU pooling and portable tensor names
and shapes are unchanged. Before export, GPU logits are checked against a
CPU copy on training representatives, and final holdout scores are calculated
with that actual portable CPU model. These execution and transport checks
do not qualify structural ranking or candidate pruning.

Large native paired blocks also support lossless byte-plane storage. The
curve arrays remain exact float64 values; byte shuffling before ZIP compression
changes no coordinates, modes, counts, amplitudes, masks or precision. Fixed
little-endian uint32 storage retains the existing sixteen-array,
48-million-element and 160 MiB expanded-data guards. Readers reject malformed
planes and noncanonical padding, reconstruct the original physical arrays,
then repeat all null-control and immutable-array checks. Repacking retains
the source checksum as provenance; it does not grant native qualification.

timing does not replace any numerical check or change generated arrays.

Continuous TOF proposals use packed native scalar columns rather than one Python

The legacy dictionary interface remains available to its existing callers.
Forward memory admission accounts both the scalar-collection peak and the

when all five float64 parameters, d spacing and window bounds are bit-identical.
It retains each reflection's intensity and original double addition order,

## Parent-reference coverage is separate from child distortion

The three-curve classifier's native parent admission uses a versioned envelope
computed only from its actual training parent-reference reciprocal metrics.
Symmetry-breaking child strain cannot enlarge that envelope. Validation and
test reference cells cannot enlarge it either. The native current-cell check
uses the same basis-invariant metric norm, including anisotropic and shear
terms. The previous generic envelope remains unchanged for legacy models.
Older paired models with only that generic envelope retain exact-parent use;
they do not claim sampled thermal-cell coverage from their child distortions.

New paired libraries sample a default parent-reference range of
0.0001–0.005 in relative reciprocal-metric norm. The previous
0.0001–0.001 range remains captured in older libraries and models; loading
them does not change their sampling or acceptance. These are synthetic
domains, not claims of full experimental temperature coverage. Actual cells
outside a model's training-only envelope retain the complete native search.
The rejection message gives both the current metric distance and trained
maximum. Broader nuisance sampling requires new physical trajectories and
qualification, rather than relaxing the inference guard. All child cell
boxes and chemistry checks remain in force; an incompatible declared range
fails explicitly instead of redrawing parent cells for selected families.

## Routing predicted families to native constructions

Stored model metadata retains every construction that generated a compatible
geometry label, including higher-symmetry special limits. At inference, an
explicit construction of the predicted space group takes priority over those
limits. If none exists, the compatible construction set remains the fallback.
This prevents a high parent score from putting every zero-distortion child
ahead of the next ranked family. Every remaining candidate is appended to the
native work order. This changes prioritization, not candidate exclusion, and
does not turn a predicted symmetry family into a uniquely identified model.

## Structural size and pattern detectability are different diagnostics

`structural_neighbor_change` reports changes in the fixed parent nearest-distance
shells, with atom identities and periodic images retained. Those contacts are
geometric neighbors, not automatically assigned chemical bonds. Supplying the
matching parent geometry at each sampled cell removes ordinary parent-cell
variation from this comparison, while retaining the child's symmetry-breaking
strain and displacements. Partially occupied coincident sites and arithmetic
boundary cases remain explicit rather than receiving an invented strong/weak
decision.

A 0.02 relative-distance change is a descriptive strong-distortion threshold.
It is not a universal diffraction detection limit. Bond-angle changes can
occur without a large nearest-distance change, and scattering contrast,
resolution and noise affect the observed signature. This report neither
removes weak examples nor changes their symmetry labels. The distance report
does not itself provide a diffraction-detectability qualification. That needs
separate coverage and observation diagnostics.

For fixed-cell displacement rays, the report helper also solves the exact
quadratic distance equations for a first 0.021 relative-distance target,
checking both compression and expansion branches. It verifies the proposed
geometry again without rendering diffraction. The proposal remains subject
to the caller's original coordinate box and chemistry checks. Failure to find
an admissible proposal cannot remove that mode or imply that its diffraction
signature is undetectable. This proposal helper is not yet the default sampler.

The paired producer also supports the internal
`radar-additive-native-mode-coverage/v2` contract. It retains every original
mixed and named-mode point and appends one endpoint to each signed mode/context
ray. An admissible contact target is checked against the matching parent cell,
the original coordinate box and the same native chemistry. If the original
endpoint is already strong, or a stronger admissible point cannot be found,
the extra row repeats that endpoint with an explicit reason. Repeated rows
are not independent examples; ordinary cohort deduplication retains their
shared physical lineage. Neither the old endpoint nor a rare or weak mode is
removed. Both original and appended endpoints retain independent native
profile checks, and resource reservations count the complete enlarged shard.
The library default still awaits full generation, capacity and accuracy
qualification; saved version-1 requests keep their original layouts.

## Exact unit-peak reuse across preparation points

The shared native TOF forward path may retain one previous unit-peak plane
inside its existing memory budget. Reuse requires bit-identical original
grids, parameters, windows and pointers, together with unchanged native binary,
wrapper, process and arithmetic controls. Every structure factor, reflection
intensity and background is recomputed. Reflections keep their original
summation order, including zero and cancelling intensities. Cell or profile
changes that do not match exactly use fresh native peaks.

The plane is disposable: it is evicted before it can reduce scalar collection
capacity or turn a previously viable batch into a workspace fallback. This
is one automatic optimization of the existing engine, not a separate fitting
method, an interpolation table or a user-selected accuracy setting. Independent
native verification remains in the generation workflow.
