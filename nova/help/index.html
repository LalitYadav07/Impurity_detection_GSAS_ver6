Start here · 01

Open the workspace and choose your path

Use one Galaxy History for the experiment you want to keep together.

  1. Open RADAR-PD Interactive in NDIP and click Run Tool. Wait for the workspace, then check the version and connection indicator.
  2. Choose Live for an IPTS series, including scans already collected. Choose Single pattern for a file you upload, select in Galaxy History, or browse in an experiment folder.
  3. If this History already contains your work, go to Reopen saved work before starting another analysis.
What you should see

The setup matches your source: Live offers an experiment selection; Single pattern offers file inputs. Neither choice starts a scientific job.

Before launching: optional service access

Ordinary phase analysis needs neither optional service. NDIP may provide shared Illumine and Bilbao access automatically. If a service is unavailable, review the session notice and the launch form’s optional ORNL Illumine and Bilbao Crystallographic Server credential groups. Do not put keys in CIFs, configurations or preparation libraries. A guided form answer does not itself need a model call. A changed launch credential applies to a new session.

Before measurement · 02

Prepare reusable model calculations before beamtime

Start with a nuclear CIF and instrument profiles; measured scans are not required.

  1. Click Prepare experiment in the workspace header. In New preparation, add the Nuclear parent CIF and each bank’s reviewed GSAS-II instrument profile. Review its profile block, type, expected range and reference grid; click Add bank context, then Inspect parent and profiles.
  2. After the inspection finishes, select the banks and finite parent-basis k scope. Choose magnetic or structural models. For magnetism, review sites, ionic form factors, g and moment bounds; for structure, review the order-parameter scope and construction limits. Click Discover model families, inspect the counts, then Prepare selected models.
  3. In Libraries and recovery, inspect per-model outcomes. Select the library you want to use and choose Back to analysis. New compatible Model and Live calculations check that selection automatically. Use Save portable library to History and download its ZIP to carry completed calculations into another session.
What you should see

The library records prepared, pending, failed and unsupported entries. It contains reference calculations, not measured patterns, fitted structures or experimental evidence.

What is reused when scans arrive?

Symmetry/model construction and compatible physical calculations can be reused. The actual nuclear structure, cell, bank, profile and grid are checked before use. Changed dependencies are rendered or rebuilt automatically; counts, variances, scores and fitted uncertainties are new for every observation. Structural starting curves do not replace the subsequent nonlinear fit. Preparation does not guarantee a seconds-long complete search.

Pause, recover or import?

Pause new batches stops new admission; acknowledged Galaxy jobs remain recoverable. Keep the session open to admit later batches. In a fresh session, Find saved preparation and Recover original work reconnect the same jobs without duplicates. Import portable library makes an independent copy of completed assets; it does not reconnect the creating session’s running jobs. Large ZIPs can be selected from Galaxy History.

Scope and service disclosure

Bilbao receives parent symmetry operations and requested k vectors. ISODISTORT receives the parent cell, symmetry and atomic sites for structural children. Neither receives measured diffraction patterns through this preparation workflow. A finite single-k candidate scope does not cover every magnetic or structural state; review omissions and unavailable models.

First Live result · 03

Let the setup assistant guide your first series

Start with a known sample and a small selection you can inspect.

  1. Choose Live, then Guided Live setup. Set Beamline, Experiment IPTS and Reduced-data folder; click Find samples and banks.
  2. Select the exact Sample IDs and names. Click Refresh banks for these samples, review the bank/profile choices, then Use these samples and banks.
  3. Continue through structures, chemistry and settings. Use Use these structures, Confirm chemistry, and Review this setup. You can return to an earlier question or choose Use the Live panel.
What you should see

The assistant fills the same Live settings shown in the setup rail. Discovery may take time; a setup reply does not start monitoring.

Example text to adapt
Full analysis; one discovery round.

Example setup reply. This limits discovery rounds per pattern; it does not limit the number of phases or launch a run. Review the resulting settings.

Choose scans and exclude unrelated runs

Open Run titles and initial monitoring scope. Review When monitoring starts, background/empty and ramp/cooling switches, and Exclude runs or reduced products. A sample ID alone does not prove that the specimen is present. Numbered assistant options refer to samples; use an explicit phrase such as “bank 2” for a bank.

Beamline-specific choices

POWGEN can match supported profiles per run; review the detected wavelength and source bank. NOMAD requires a reviewed supplied profile and physical-bank mapping. HB-2A and SNAP retain preview status and additional normalization/profile checks. Follow the notices for your selected source; do not copy another instrument’s profile.

First Live result · 04

Choose structures, chemistry and a matching profile

Give the search the structures and instrument description it is allowed to use.

  1. In Candidate structures, choose the built-in catalog, an existing portable library, or build a mini-library from reviewed CIF files/CIF ZIPs. Wait for Library ready and check the usable and rejected inputs.
  2. Use Dominant-phase CIF only for a known dominant phase. Possible impurities belong in the candidate library. Review Sample element symbols and optional environment symbols; Use CIF element suggestion is a starting point.
  3. Check the selected source bank against the Instrument profile. In settings, review the native fit interval, exclusions and background. Use Inspect a representative curve before accepting a suggestion.
What you should see

A usable library is selected, your element list covers plausible sample phases, and the profile/fit range matches the chosen data.

CIF ZIP or portable library?

A ZIP of source CIFs is material for a library build. A finished portable library is a different input. Building checks usable structures; it does not prove phase identity. A two-structure library cannot discover an absent third structure. Obtain licensed CIFs through a source you may use; they are not redistributed here.

Reuse settings without copying a specimen

A saved configuration supplies analysis settings. The current Live selection still supplies scans, profile, library and dominant phase. Use Edit a copy to make a new draft. The AGES configuration has experiment-specific ranges, background and exclusions; inspect it rather than adopting it as a general default.

TOF peak-profile treatment

Keep the supplied profile fixed by default. For an explicit main-phase CIF, advanced per-scan adjustment can release available histogram X/Y/Z width coefficients in one separate checked stage before residual searches. Position calibration stays fixed. Failed or correlated adjustments retain the supplied profile. For reuse across a series, supply a reviewed reference profile and keep Fixed. This empirical width adjustment is separate from atomic x/y/z and can absorb genuine broadening; inspect raw transition evidence independently.

Full, Rapid and background choices

Balanced discovery is a useful first setup goal. Rapid hypotheses ranks bounded alternatives and refines a selected number; inspect which hypotheses received a final refinement. A background suggestion is an aid to review, not an automatic scientific acceptance. Increasing search effort cannot fix the wrong data or instrument profile.

First Live result · 05

Check the setup, then test one scan

Catch a wrong selection or profile before processing a series.

  1. In the assistant, click Check Live configuration, review its summary, then Finish setup. In the Live panel, the equivalent check is Check experiment and inputs.
  2. Read the selected cohort, excluded runs, bank count, resolved profile and blocking reasons. Resolve a mismatch before continuing.
  3. Use Test latest scan and, if offered, Bank for the one-scan test. Inspect that result before clicking Start monitoring for the series.
What you should see

The check reports the intended inputs. A one-scan test creates one analysis; continuous monitoring remains stopped until you start it.

If Start stays disabled

Read the blocking reason near the check. Common causes are an unfinished library build, no selected sample/bank, an unreviewed profile mapping, or invalid settings. The Connected indicator only describes the session connection; it does not certify scientific inputs.

Analyzing a single file instead

Choose Single pattern. Work through Measurement Type, Candidate Library, Data Collection and the analysis settings. The pattern, profile and optional main-phase CIF can each come from different sources. Select the correct pattern geometry and units, then review the settings before Run analysis on NDIP. Reopen its result through Open Previous Run. The Live assistant is not required for this path.

First Live result · 06

Start the series and follow its queue

Separate preparation and waiting from completed scientific results.

  1. Click Start monitoring once. It saves the validated Live configuration and follows the selected existing/new reduced scans while this session runs.
  2. Use Hide setup for more space. Expand Monitor setup and processing summary; read Queued, running and failed scans and each row’s Current activity.
  3. Open Results as scans finish. Check an unexpected delay in the queue details and Galaxy History before starting another run.
What you should see

The dashboard says Monitoring. Results arrive per completed analysis; preparation, Galaxy waiting, execution and result collection can take different amounts of time.

What continues when you stop?

Stopping monitoring prevents further discovery/submission by this watch. Already-submitted Galaxy jobs continue. A browser session is not an unattended facility service. To inspect jobs that finish after stopping, use Refresh saved results; to restart the same saved watch, use Resume existing watch.

A failed or paused item

Read the item’s full activity and the associated Galaxy job. A failed input transfer differs from a scientific failure, and a paused Galaxy job differs from stopping the Live watch. Retry the indicated failed operation after resolving its cause; do not launch a duplicate series to repair a single item.

Read the results · 07

Inspect one fit before trusting a trend

Check that the fitted model explains the measured pattern.

  1. Select a completed scan in Results and open its full result. Expand the fit.
  2. Inspect observed and calculated curves, the residual, and each phase’s Bragg ticks. Zoom both a strong-peak region and weak unexplained signal.
  3. Read the reported convergence/qualification notices and resolved settings. Keep the selected scan, bank, fit interval and checkpoint with your interpretation.
What you should see

You can identify which scan and model produced the fit, where discrepancies remain, and whether a verified refinement is available.

Reading Rwp and phase fractions

A smaller Rwp is useful only for a comparable data domain and weighting. It does not establish a unique structure. Fractions describe the fitted crystalline model; missing phases, amorphous material, texture or calibration errors can affect interpretation. A completed job can still need scientific review.

Read the results · 08

Plot phases, lattice changes and error bars

Keep every plotted value tied to its scan, units and source refinement.

  1. In Results, choose Samples shown, Phases shown and an eligible Horizontal axis.
  2. Open Additional plots and derived quantities. Select the saved view or lattice quantity, phases and absolute/relative representation. Enable error bars when available.
  3. Open Data behind this plot to inspect values and unavailable/excluded reasons. Save view settings and use Download views and observations for full-precision data.
What you should see

Axis labels include units, the legend distinguishes phases/signals, and exported observations identify their source and uncertainty status.

Missing axis, gaps or missing error bars

Only qualified acquisition conditions can be used. A run-title temperature is not automatically a specimen measurement. A range during a scan is not a standard uncertainty. Fixed or unavailable parameters may have no error bar; a missing value must not become zero. Refinement errors are conditional on the model and calibration.

The historical temperature example

The reviewed AGES mapping corrects that recorded cohort only. Use exact run IDs and an explicit, reviewed source for your own mapping. Relative lattice change needs a stated reference; it is not an absolute thermometer.

Read the results · 09

Follow measured changes across scans

Use the map to locate evidence, then inspect the compared curves.

  1. Open Transition tracking. The default Transition evidence view is Full-Q U-Net (experimental). Choose one Sample / bank / reduction series and Inspect scan.
  2. Set Arrange scans by, Direction and Compare each scan with. Choose U-Net feature overlays, then inspect the linked heatmap and measured reference and selected curves. The tab brings the comparison and map into view and hides setup; use Show setup to reopen it or Focus plots to return to the map. Use the vertical scan slider to move through the series. Open How to read this map for the display guide.
  3. Review local boxes, the four whole-pair cause suggestions, joint Q coverage and exact profile provenance. Inspect the RADAR-PD fits and Bragg ticks when available. Use Reset zoom as needed.
What you should see

The selected scan and map agree. Colored boxes mark model-suggested local changes. Cause scores are uncalibrated suggestions, not confirmed phase identities; missing Q coverage is disclosed.

Compare legacy boundary indicators

Choose Boundary indicators (legacy) under Transition evidence to reproduce the earlier indicator view. Select Indicators used for boundaries, Indicators required and Boundary comparison. The count is a rule, not a probability or independent vote.

Why can a feature have no box?

A whole-pair cause suggestion can occur without a supported local box. Unverified instrument profiles, insufficient shared Q coverage or changed banks can prevent inference. Review the measured curves and profile before interpreting a suggestion as a physical transition.

Optional: refine further · 10

Build, review and run a refinement recipe

Make a controlled change to published GPXs while keeping the original results.

  1. Open Refinement → Recipe and Refresh projects. Select the experiment, Apply recipe to scope, banks and a Representative GPX. Click Inspect starting model.
  2. Choose Recipe setup: Guided recipes asks structured questions; use Start / restart guided setup, Use this answer and Build and check recipe. Expert request accepts a bounded request and Generate recipe.
  3. If clarification is needed, use Answer the questions above and Use answer and revise recipe. Review every stage, fixed parameters, explicit edits, bounds and scope. Click Approve recipe and scope, then Start refinement. Approval and execution are separate actions.
What you should see

The displayed stages release only the intended parameters. The queue reports each scan’s verified progress and retains the original project.

Example text to adapt
Create two stages: first refine existing background coefficients and phase scales; then add unit-cell parameters. Keep atom positions, occupancies, displacement parameters, instrument/profile, sample broadening and texture fixed. Keep the current fit limits. Explain any unsupported request before proceeding.

An example for Expert request, after inspecting your actual GPX. Review the generated stages; do not approve it merely because it resembles this text.

Fix a phase model before refining it

Correct the phase model can replace, add or remove a phase. Inspect the source, supply a reviewed CIF and reason, and create a separate corrected model. It needs a new recipe. Occupancy recipes require an applicable held reference; a refined scale is not a chemical occupancy or weight fraction.

Choose a finite scope first

Selected saved results pins exact GPXs. Samples/all-results scopes can enroll future compatible arrivals if Enroll future matching scans is enabled. Recipe revisions replace approval and pause future enrollment. Pause stops new enrollment while active jobs finish; Resume queued runs queued scans. Future enrollment requires Start refinement.

If a stage stops or needs attention

In Expert request, If a stage fails scientific checks lets you stop or restore the preceding checkpoint and continue independent stages. Review declared dependencies before approval. Rejected values are discarded; dependent stages are skipped. Earlier verified GPXs remain selectable in Model exploration and Stage for trends. Retained stages carry their review notices. Use Retry transport only for an indicated transport problem.

Optional: refine further · 11

Compare stages and preserve the native project

Assess what changed, including parameters that remain weakly determined.

  1. In Refinement → Refined results, select the scan, recipe and stage. Use the fit, trends and parameters views to compare with the original on the same fit interval.
  2. Inspect conditional uncertainties, held values, parameter bounds and stage provenance. Separate a completed computation from scientific acceptance.
  3. Choose the required artifact and Download, or open the selected GPX in the hosted GSAS-II desktop. Save and close that desktop before opening a different GPX.
What you should see

The selected output has a named scan and stage, a verified source, and a native GPX you can locate again in Galaxy History.

A lower residual is not enough

Check whether added freedom is identifiable and physically plausible. Conditional errors omit model and calibration uncertainty. Phase HAP scales are not weight fractions; use weight values only when GSAS-II derives them. The archived AGES example deliberately used different fit intervals for base and later refinement, so its raw Rwp values are not a like-for-like improvement comparison.

Optional: model research · 12

Explore magnetic or structural alternatives

Compare a reviewed finite hypothesis set from an exact parent GPX.

  1. Open Refinement → Model exploration. Select Starting GPX · original or recipe checkpoint and Inspect exact parent. Choose Exploration: Magnetic models or Structural displacement modes.
  2. For magnetism, review the parent sites, ionic form factors, moment model, bounds and rational k vector. If k is unknown, use Find candidate k-vectors, inspect its coverage, and Use selected k. For structure, enter the rational k and review the parent reference, candidate scope and displacement/cell bounds.
  3. Click Discover finite candidates, review constructed models and Scans to refine. Structural fits retain every independent physical displacement coordinate. Choose the current scan, a searchable selection, or all compatible scans. Then Build finite plan, review its counts, Approve finite plan, and Start approved campaign. Future matching scans are a separate option.
What you should see

A finite campaign records the tested models, starts and exact scan/bank. Inspectable alternatives and unresolved trials remain visible alongside successful fits.

What the search does and does not establish

Commensurate k surveys run their finite declared template set. Inspect tested/planned coverage and the provisional leader. The residual view includes nuclear-model errors; magnetic Bragg markers show calculated reflection positions, not proof that measured peaks have been indexed. In Moment direction in parent frame, choose a, b or c with Compare moment with parent axis. This displays a geometric projection onto that direct axis, including for nonorthogonal cells; it does not alter the fit or establish canting. Constructed structural candidates depend on supported parent/mode mappings. Calculated-pattern groups can contain indistinguishable models. Retain the receipt, source GPX and scientific qualifications.

Choose compute without confusing it with search quality

Compute budget defaults to eight concurrent Galaxy batches for independent models and scans. Requested workers are bounded by the actual scheduler allocation; an unreported allocation permits one native worker per job. Analysis, recipe and model jobs share the History-wide capacity limit. Polishing jobs also have their own budget. Pause all active campaigns and Load saved campaigns/Continue saved campaign support recovery. Saved campaigns retain their selected concurrency. Increasing concurrency does not expand the approved scientific model set.

Structural fits and preparation failures

Structural models use one prepared native workflow. The default is four starting guesses and up to 120 seconds of optimization per model; construction, starting curves and independent GPX verification take additional time. An optional Parent reference GPX supplies coordinates and ADPs while target data and instrument settings are retained. Check parent peak widths first: an incorrect profile can mimic symmetry breaking. Construction details lists failures and deferred models; no plan is offered if none is ready. A verified structural point fit remains Optimization unresolved and reviewable; it is not a unique structure determination or a covariance-based uncertainty estimate. The parameter table shows the child cell and normalized ISODISTORT amplitudes; these amplitudes are not individual atomic displacements. Native Bragg ticks use the selected child symmetry. Missing error bars remain unavailable. Batch counts distinguish model fits from their internal starting guesses.

Advanced magnetic optimizer choice

Fast checked optimizer · fixed nuclear model supports commensurate k, symmetry-allowed components and one neutron histogram. It reuses a checked native quadratic model across starts and verifies results against GSAS-II. It does not supply native covariance error bars. GSAS-II Hessian remains available. Both require a scientifically reviewed nuclear baseline; unsupported inputs stop with a reason.

Optional: model research · 13

Inspect a POWGEN acquisition in progress

Use provisional WebMON snapshots with explicit reference assumptions.

  1. For a saved POWGEN watch, open Live acquisition. Select Viewed scan or Follow latest matching scan, then Refresh source. This reads snapshots; it does not start the completed-scan analysis queue.
  2. Choose Live analysis: magnetic or structural models. Load a published nuclear GPX, inspect its original fit, and review the producer’s physical bank, conversion and normalization. For magnetism, expand Review nuclear reference & magnetic assumptions, set/discover candidates in Refinement, then Prepare reviewed live models in Galaxy.
  3. For magnetism, review the exact reference and bounds before Start magnetic analysis; Analyze updates for this run follows revisions. For structure, use Set structural models in Refinement, build and approve the finite plan, return here and Use approved structural plan. Choose Fit current structural snapshot once or Follow structural updates for this run.
What you should see

The display identifies the viewed run, analyzed run and input revision. Fits and moment intervals are conditional on the reviewed fixed nuclear reference.

Availability and interpretation

This tab is available only for POWGEN when the deployment configures its WebMON source. The GPX instrument constants alone do not validate WebMON’s producer mapping. A changed revision can make a displayed result stale. Browsing a new scan does not move an already pinned analysis. Updates replace the likelihood for a cumulative snapshot; they are not independent extra observations.

Structural snapshots and recovery

Structural fitting uses the reviewed complete displacement/cell model portfolio and reports every model’s outcome. Select a completed fit to inspect its native curve, Bragg ticks, cell/mode point estimates and continuation GPX; switch d/Q/TOF or reset the zoom. Open continuation in GSAS-II opens that exact checked project in the hosted desktop; save and close an existing desktop first. These remain point fits requiring optimization and scientific review, not structural posteriors. Changing the transfer settings or producer mapping requires adopting the plan again. Pause automatic analysis retains the latest pending revision. Stop waiting for jobs does not cancel accepted Galaxy work; use Recover structural jobs before another snapshot is admitted.

No automatic counting decision

Review Scientific use and reference-quality notices. Conditional moment intervals and credible envelopes do not establish absolute accuracy, and the current workflow does not recommend when to stop counting. Review completed analyses in this workspace reloads an indexed result; Galaxy retains published bundles after the viewer closes.

Save and recover · 14

Reopen saved work without duplicating jobs

Recover a watch, a result or a model campaign through its saved record.

  1. For one analysis, expand Open Previous Run, search the current History and Refresh from Galaxy if needed.
  2. For a Live series, open Restore a saved Live watch (stopped). List saved watches, select a Saved Live checkpoint, Inspect selected checkpoint, then Restore stopped watch.
  3. Review the restored identity/counts. Use Refresh saved results to collect existing jobs, or Resume existing watch to resume discovery. For models, use Load saved campaigns and review before Continue saved campaign.
What you should see

Restoring opens saved work with monitoring stopped. It does not submit a new analysis; refreshing and resuming have distinct effects.

A restored watch and the editable draft differ

The restored watch keeps its saved experiment and configuration. Changing the setup draft does not retarget it. Review the watch shown above the results; clear the workspace before configuring a separate watch. If recovery is read-only or blocked, inspect its stated restrictions instead of using Start monitoring as a substitute.

If a connection closes

Return to the same Galaxy History and open a new RADAR-PD session. Recover published records and inspect ongoing jobs before resuming. The old interactive URL is not a permanent report. Saved artifacts, not the browser tab, are the durable record.

Save and recover · 15

Contact the developer

Send a question, bug report, feature request or message without sharing your experiment History.

  1. Click Contact developer immediately left of End session.
  2. Write your message. Optionally choose a category, add a reply contact, attach an image or paste a screenshot into the message field. Review every preview and remove anything you do not want to send.
  3. Click Send privately. Keep the Galaxy browser signed in as this session's owner. Wait for the delivery reference; uploads may still be processing. If delivery fails, retry the unchanged report or download its ZIP.
What you should see

A verified report reference and Open saved report link appear. The developer receives a separate private feedback History; your analysis History is not shared.

What accompanies a report

Only your text, chosen images, optional reply contact, Galaxy username/email, application version and current view. Keys, logs, configurations and scientific arrays are not automatically attached. Screenshot metadata is removed.

Find the report later

The report remains in Galaxy after End session. Developers open Histories shared with me; reporters retain their own report History. Download a draft before closing a session if delivery has not been confirmed.

Save and recover · 16

Save, clear or end the session deliberately

Keep the scientific record and stop only the work you intend to stop.

  1. Locate the needed configurations, observations, recipes, receipts and native GPXs in Galaxy History. Download the specific output you intend to share.
  2. Stop monitoring and future enrollment when finished. Use Clear workspace to reset the viewer for a separate study; read its confirmation.
  3. Use End session to release the interactive container. Review active Galaxy jobs separately if you intend to cancel them.
What you should see

Saved outputs remain in Galaxy History. Clear/end stop session-bound monitoring and queued/future work; already-submitted Galaxy jobs continue.

Keep a reproducible result together

Record the scan and bank, input/profile/library, applied configuration, native checkpoint, recipe or model plan, and its qualifications. Screenshots help explain a result; full-precision observations and the native project preserve it.

When something does not look right

Find the next check

My uploaded input is missing

Use Refresh History inputs in the assistant after uploading to Galaxy. Check that the dataset is ready and is the expected type. A local CIF ZIP is not an already-built portable library.

Discovery is slow or lists the wrong samples

Confirm beamline, IPTS and reduction folder; then let background discovery finish. Review exact IDs, run titles and source family. Archived, sliced and summed products can have separate identities.

The plot is blank or a value is missing

Check the selected sample/bank, scan status and eligible axis. Open Data behind this plot and read qualification/exclusion reasons. A fit may not be available until its job publishes outputs.

A recipe is complete but I cannot use its final value

Inspect the selected stage and convergence/bounds notices. Some values are fixed, unavailable or retained from an earlier verified stage. A completed transport is not scientific acceptance.

I cannot see Live acquisition

It is a configured POWGEN-only workspace. Select the proper saved POWGEN watch; other beamlines and deployments without a WebMON source do not show the tab.
